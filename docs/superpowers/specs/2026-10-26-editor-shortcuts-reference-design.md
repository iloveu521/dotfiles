# VS Code 与 Neovim 快捷键查询页设计

## 意图

给常用编辑动作提供一个一眼可查的 VS Code Vim 与 Neovim 对照页，减少记快捷键和来回翻配置的成本。界面使用中文说明、原样展示按键与 Vim 模式。

## 范围与约束

- 只整理当前已配置且常用的编辑、移动、搜索替换、代码跳转、补全/多光标和文件查找快捷键；Vim 原生命令会明确标注。
- 数据以 VS Code `settings.json`、`keybindings.json`，Neovim 的 `KEYMAPS.md` 与 Lua 映射为准。
- 搜索支持按键、动作名和常见中文词；过滤器可按编辑器和类别缩小结果。
- 本地离线使用，不启动服务器、不部署、不修改任一编辑器快捷键。
- 设计采用淡紫、淡粉、淡绿玻璃质感卡片，同时保持正文与按键标签高对比度；支持键盘操作和窄屏布局。

## 实现方案

1. **单文件离线 HTML（推荐）**：页面、样式、搜索交互和映射数据放在一个 HTML 文件。双击即可打开、无依赖，符合 dotfiles 内随手查询的用途。
2. **多文件本地小站**：拆分 HTML、CSS、JS 与数据，后续扩展更清楚，但从本地文件打开数据会受浏览器跨源限制，通常还需起本地服务。

本任务采用方案 1，目标文件为 `docs/editor-shortcuts.html`。

## 页面结构与交互

- 标题区说明这是当前配置的编辑快捷键索引，并标明 Neovim `<leader>` 是空格。
- 搜索框匹配按键、功能、别名和说明；过滤按钮提供“全部 / 两边共用 / VS Code 专属 / Neovim 专属”以及编辑类别。
- 结果按类别分组；每行显示动作、VS Code Vim 按键、Neovim 按键、模式与必要说明。
- 页面分成“当前配置映射”和“Vim 原生速查”两块，避免把用户自定义映射误认为 Vim 内置功能；原生速查要涵盖模式、移动、操作符与文本对象、行编辑、搜索和替换实例。
- 显示 Leader 的适用范围：Neovim `<leader>` 是空格；当前 VS Code Vim 配置没有 Leader 映射。
- 解释多光标行为：VS Code `Alt+P` 绑定 `editor.action.selectHighlights`。用户实测执行后 `a` 没有反应、`i` 会对全部选择生效；页面按这个实际观察说明，避免称为 Leader 序列或声称它在所有环境下行为一致。Neovim 的 `Alt+P` 则是其多光标插件的全部匹配映射。
- 无结果时给出可清空搜索的提示；匹配数量通过状态文字更新。
- 页面使用本地 CSS/JavaScript，不加载远程字体、图片或脚本。

## 视觉与无障碍

采用雾紫底色和淡色玻璃面板，使用清晰边框与深色正文/按键字，避免浅色文字只靠颜色传达信息。搜索、筛选和清除操作使用原生表单控件，提供可见焦点、语义标签、窄屏重排与减少动态效果支持。

## 不做的事

不发布到公网、不创建后台、不自动改写快捷键配置；不把未经当前配置确认的 VS Code 默认键位混入“已配置”映射。
